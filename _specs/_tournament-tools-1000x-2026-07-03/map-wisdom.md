
THE ARSENAL — Strongest forms/devices NOT yet wired into the app's tools

1. THE 8-POINT TAPPING LADDER AS A RITUAL METRONOME (Tony tapping — TONY-ANATOMY.md §1)
The ladder (eyebrow → side-of-eye → under-eye → under-nose → under-mouth → collarbone → under-arm → top-of-head) is a proven time-scaling grammar: any round is 4.5 min at full dwell, compressed to sub-30s at tap-pass speed. Not one of the 82 engine beads uses it. The ladder = a modular "round" slot the composer can fill with any payload (gratitude, future-visioning, affirmation install, body-scan) by swapping the dwell content without changing the container. The existing breathwork() surface (app.js:4519) has no equivalent structural container — it is a single breath-form, not a multi-station traversal.

2. THE 0-10 GAUGE + PRE/POST DELTA AS IN-APP REWARD (TONY-ANATOMY.md §2, mechanic #4)
Tony's own app marks the user's stress number before and after every session. The delta IS the payoff — visible self-regulation proof. ALTER has mood (0–4 via currentMood) but never shows a before/after delta that makes the intervention's effect legible. This is both a missing retention mechanic and the backbone of the "efficacy lab" / prescription engine mentioned in the mining notes.

3. SPEAK/LISTEN ALTERNATION — ROUND TYPES AS DISTINCT MOODS (TONY-ANATOMY.md §1)
Release/install rounds are voiced out loud ("more congruency — whole nervous system engaged"); gratitude/reflection rounds are listen-only. The app has no concept of these as distinct surface types. This is actionable as: voiced rounds = user speaks into a bubble that echoes back; listened rounds = guardian speaks + dwell gap (~12-20s). The distinction produces emotional range across a single session.

4. THE SETUP STATEMENT FORM WITH EMBEDDED HONOR-THEN-PIVOT (TONY-ANATOMY.md, mechanic #6)
"Even though [honest negative truth], I [acknowledge this] and choose [resource state]." This is not reframing or positive thinking — it honors the negative before pivoting. The app's current shame-prevention is structural (no guilt labels, no red) but has no voiced form that names the bad thing first. The setup statement is the missing voiced anti-shame device.

5. RAISE + DIRECTION/RELEASE + FORGET AS RITUAL BEATS (POP-MAGICK-MINING.md §1, Grammar upgrades section)
The magick source adds three named beats the app's ritual grammar entirely lacks: RAISE (pre-ritual physiological arousal — movement, palm-rubbing, one song — to prime state before the cognitie work begins); DIRECTION + RELEASE (building intensity to a peak then dropping it on a long exhale — the tension-discharge beat); and FORGET (post-ritual detachment: "let it go, let it work" — anti-rumination close). The current app grammar is ARRIVE → BREATHE → INTENTION → CLOSE. It has no raise, no peak-release beat, and no explicit forget signal.

6. SIGIL GENERATION AS A PERSONAL CODED ANCHOR (POP-MAGICK-MINING.md §1, mechanic #4)
Intention sentence → strip vowels/repeated letters → weave remaining letters into a private glyph → charge via repetition → forget. The glyph is a personal retrieval cue with encoding specificity. The mining notes specifically suggest the app could auto-generate the glyph from the user's own intention text using the vowel-strip algorithm and then use it as the icon of a compiled ritual shortcut. This would be the app's most literal "scientific grimoire" expression — every object's power is conditioned anchoring, made visible.

7. CANDLE AS DE-CLOCKED TIMER + TWO-CLOSE GRAMMAR (POP-MAGICK-MINING.md §2)
A candle flame as trance focal replaces a countdown. The burn IS progress — no number needed. The two distinct closes (blow-out = release/done; leave-burning = intention is "running" all day) encode different states of commitment. Neither a visual timer metaphor nor a "session still active" ambient state exists in the current app.

8. THE MAGICKAL RECORD = AUTO-CHRONICLE (POP-MAGICK-MINING.md §1, mechanic #6)
"Log date/ritual/emotional state/physical condition/results; study variables of rituals that worked; repeat those variables." This is already encoded in the engine as the prescription engine concept (pre/post gauge delta per tool/section → composer weights rounds accordingly) but no bead or surface calls it by function. The Magickal Record mechanic is the bridge between the per-session gauge delta and the long-run prescription engine — it is named but not yet a first-class object.

9. SOM vs AOM INTENTION TAXONOMY (POP-MAGICK-MINING.md §1, mechanic #5)
Specific-outcome ("I will land client X by Friday") vs abstract-outcome ("more calm, more ease") as two legally distinct intention forms. The current engine treats all intentions the same. SOM is higher-chaos, AOM is safer for repeated use. The intention-setting step in every morning tool could offer both forms as a chip-pick, with the AOM path branching to virtue/state rather than goal.

10. THE FOUR-FACET COMPASS AS A TONAL SWITCHING LAYER FOR THE GUARDIAN (plotkin-fold.json, guardianAmendments)
Four tonal registers (build/feel/lighten/imagine — de-cheesed from Plotkin's North/South/East/West) the guardian switches by user gravity. Not four modes a user sees, but four stances the guardian's copy adopts invisibly based on what the user's recent log data orbits. A grind-heavy user gets the "feel/body" nudge; a detail-spiraler gets the "zoom out/lighten" stance. This is buildable as a copy-switch layer over the existing guardian hero line — no new surface, no visible label.

11. GRAVITY-AS-DERIVED-READ (plotkin-fold.json, vet.buildable, bigReframe)
A pure derived read over existing logs/blocks/bead use that classifies what the user's recent attention pools into: self-care / craft / virtues / people / service. This is the first non-XP progression signal in any of the mines — it progresses when attention shifts, not when streaks or tiers rise. The engine currently has journeyPhase (how long / how broad) but no gravity axis (WHAT the days orbit). Fully data-safe: no SCHEMA bump, pure read.

12. RELAPSE-IS-A-NODE + RETURN-COUNT AS TRACKED WIN (plotkin-fold.json, journeyArcAmendments)
When a habit/streak breaks, the path renders the lapse as a forward "you came back" node with a tracked return-count, not a reset or miss. The existing engine has turnaround-catch and bounce-back-stat but they fire on return — they do not render the lapse itself as a named milestone on the path. This is distinct from not-showing-a-miss: it actively rewards the return act as a node type.

13. THE FOUR WILD MIND SUBPERSONALITY ARCHETYPES AS NAMED INNER VOICES (Wild Mind Ch. 6–9 + plotkin-fold selfModelAmendments)
Loyal Soldiers (inner critic / protector / flatterer), Wounded Children, Addicts/Escapists, Shadow Selves — not as therapy, but as the source material for the "named protective voice" mechanic. "The You'll-mess-it-up voice is trying to keep you safe — go anyway, small?" This externalizes the drift/stall into a named, known part rather than a character flaw. The mining's de-cheese: opt-in, max 3, surfaced only at the live micro-stall moment, one gentle line.

14. LIVING QUESTION AS A GENTLY-BRIGHTENING BEAD (plotkin-fold.json, newBeadsOrSurfaces)
A question the user and guardian name together that is genuinely unresolved — ALTER rewards revisiting it across days without forcing resolution. Resolving early gives LESS reward, not more (revisiting brightens). This is the structural opposite of every existing worksheet bead, which demands an answer. The "living question" bead is the only one where sustained not-knowing is the achievement.

15. THE ACTION BRIDGE AS THE MEDITATION-TO-DAY HANDOFF (TONY-ANATOMY.md §2, mechanic #8)
Every Tony session ends with a single action question: "What's one action I can take today to get a step closer to my most important goal?" The answer becomes the day's one-thing node. This is the RELIEF DOOR → STRUCTURE DOOR hand-off. The engine has night-before-seed (plants tomorrow's one-thing) but no equivalent forward-handoff from within a mid-session meditation to the planner.

SEQUENCING WISDOM — Order, timing, and adaptation principles from across the mines

FROM TONY (TONY-ANATOMY.md §1):
- REGULATE BEFORE REPROGRAM: the body scan + gauge-in always precedes the cognitive content. Side-of-hand setup is the regulator — it comes before any gratitude or future-visioning round. This confirms the engine's "acute override → regulate first" principle with a specific grammar.
- MORNING PAYLOAD vs EVENING PAYLOAD are formally distinct: morning = draw → install → act-bridge (pull, set intention, generate one action); evening = story-authorship → question-ladder → body-scan-to-sleep (reflect, reframe, discharge). Same grammar, opposite charge direction. This cleanly maps to AM (aim the day) vs PM (close the loop) and resolves the current "bookend feels clunky" problem — the bookends stop being forms and become ritual grammar.
- ACTIVE BEFORE STILL inside each session: RAISE beat (movement/arousal) → breath → cognitive content. Not a rule about sessions before meditation — it is the within-session order.
- LENGTH SCALING via rounds × dwell-per-point: 2-min session = gauge + release + 1 round + gauge; 15-min = 3–4 rounds. This is an explicit density dial — the same grammar scales from phone-open to deep-work context.
- CLOSE WITH A LAW: every session exits on one memorable line (rotating pool). This is the closing-law device — not a summary, a single truth that travels with the user after session end.

FROM POP MAGICK (POP-MAGICK-MINING.md):
- RAISE → INTENTION → DIRECTION/RELEASE → FORGET: the four-beat magick arc. RAISE primes state; INTENTION focuses it; DIRECTION/RELEASE discharges at peak; FORGET detaches (prevents over-gripping / ironic-process interference). This is an AM arc shape.
- TIMING AS CADENCE SKIN: waxing (draw in / set intentions), full (power / the big charge / week-aim), waning (release / letting-go rituals / quit work), new (beginnings / reset). This maps onto the app's weekly/monthly review rhythm as an optional aesthetic layer — the mechanic is cyclical planning, the skin is lunar.
- THE RECORD CLOSES THE LOOP: every ritual generates a log entry (emotional state, physical condition, results, coincidences noticed later). The record is not documentation — it is the feedback loop that makes the prescription engine possible. Without the record, sessions don't learn.

FROM THE ENGINE-V1 SEQUENCER (engine-v1.json, canon-fold.json):
- SCARCEST RESOURCE DETERMINES FLOOR FORM: beyond energy, the compose() resolver should read the one most-depleted resource and shape the floor form to relieve THAT specific resource. Late-day + nothing logged = time-scarce → tap-pass floor; mood low but time fine = brain-cycles-scarce → single-tap floor; new habit with no anchor = non-routine-scarce → anchor-it floor. "No time? Two taps. Done."
- ONBOARDING BIASES COMPETENCE-DEMONSTRATIONS (first 5 days): flip-the-switch, morning-intention, consistency-chain. Scaffolding (weeks 2–8): ownership + nearly-reached goals (woop-plan, week-scorecard). Endgame (90+ days): creative/reflective beads (win-and-learn, philosophy-handbook, make-it-yours). journeyPhase as the lifetime maturity axis driving braid-weight, not just tier.
- ANTI-GRIND LAW: the soulArc never fast-tracks when a user rushes. Depth in the current chapter is the only accelerant. Plateaued users (high streak, pinned floor appetite, no chapter advance) get one "next horizon" optional coin — never pressure to graduate.
- ANTICIPATE AT THRESHOLD, NOT AFTER: normalizing copy fires at the predicted hard moment (first return after a miss, wk-2 flattening, first ceiling reach) BEFORE the user concludes failure. One line pre-empts self-blame — surgical.
- REWARD-NEVER-SHAME IS AN ADAPTIVE GLIDE: as the user's self-driven ratio (intrinsic bead completions vs extrinsic pings) rises, celebration frequency damps and reflective beads get more airtime. Not a flat rule — a moving migration.

FROM PLOTKIN (plotkin-fold.json):
- GRAVITY SHIFT (not XP) IS THE REAL PROGRESSION SIGNAL: the soulArc advances when attention moves (self-care → craft → people → service), not when streaks rise or tiers complete. This is the second, orthogonal dimension to journeyPhase.
- SAME DIFFICULTY, DIFFERENT KIND OF TASK: a Thespian-gravity user (orbiting approval) gets "do one thing today no one will see"; a Wanderer-gravity user gets "sit with the question"; an Explorer gets "try something you've never tried." Same effort, categorically different task type. This is what developmental sensitivity looks like as a compose() branch.
- MEET THE WANDERER DIFFERENTLY: "everything feels off / I don't know what I want" → do NOT return to the plan. The wrong move is forcing a new goal. The guardian holds the lostness and does not prescribe.
- CONFIRMATION BEFORE IDENTITY-DEPTH: the guardian must reflect that who the user already built is real and enough before any "find your true self" depth prompt unlocks. Reassurance is the precondition for depth, not its obstacle.
